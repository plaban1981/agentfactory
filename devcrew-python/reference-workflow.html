Trustworthy Agent Factory · Architecture & Runbook

From a typed task to a verified,
deployed pull request.

A stateless control panel dispatches real GitHub Actions jobs. An AI agent edits code, an isolated container tests it, an independent model reviews it, and a fail-closed lineage gate decides whether anything may be published, merged, or deployed.

3End-to-end execution

What happens, in order, when an operator submits a task with auto-merge enabled — and exactly which code runs at each point.

  1. 1

    Operator logs in

    The browser builds a Basic header and stores the GitHub token in JS variables. refresh() calls status + runs in parallel; the workspace appears only if both succeed.

    factory.js › refresh()control.py › authenticate()github_token()
  2. 2

    Task is dispatched

    POST /api/factory/tasks validates Task (10–10 000 chars), then calls github('actions/workflows/factory.yml/dispatches') with ref=main and inputs task, auto_merge. Response is 202 “submitted”, never “done”.

    control.py › dispatch()GitHub REST
  3. 3

    Job ① implement — the agent edits code

    Fresh checkout (no persisted credentials). agent.implement() loops: completion() → OpenRouter → tool calls → tool() → safe_path(). Workflow, deploy, Dockerfile, .env*, factory_ci/ and agent_factory/lineage/ are protected. A git diff (≤500 kB) becomes the patch; implementation.json records the binding and provider receipts.

    factory_ci.agent implementOpenRouter (coding model)upload factory-patch / -implementation
  4. 4

    Job ② test — isolated, trusted measurement

    validate-patch rejects binaries, deletions, symlinks, mode changes, odd paths and lineage edits; git apply; docker build ci.Dockerfile. Then lineage execute --name tests runs pytest inside a container with --network none --read-only --cap-drop ALL and a read-only source mount. The parent process writes tests.json with the real exit code, output digest and binding.

    lineage.validate_patch()lineage.execute()Docker
  5. 5

    Job ③ review — a different model family judges the patch

    agent.review() sends task + patch (treated as untrusted data) to REVIEWER_MODEL. Startup refuses to run if coding and reviewer models share a provider prefix. Anything other than approved:true plus a reason raises and stops the pipeline.

    factory_ci.agent reviewOpenRouter (reviewer model)
  6. 6

    Job ④ publish — the lineage gate decides

    publication_gate() collects implementation, tests and review records, queries GitHub for the live main SHA and the real job outcomes of this attempt, then admit('publish'). Only on allowed does it create blobs → tree → commit → factory/run-<id> → pull request. lineage.json is uploaded always, including on failure.

    lineage.publication_gate()admit()publish.main()Git Data API
  7. 7

    Merge (only if auto_merge)

    publish merge re-reads the PR, requires state open, head SHA equal to the admitted commit, base main, same repo; re-runs admit('merge') against the current base; then calls the merge API with sha=<admitted head> (squash).

    publish.merge()admit('merge')
  8. 8

    Job ⑤ deploy — verify the result, then ship

    Calls containers.yml (workflow_call): real tests again, build image with version+revision labels, stage on loopback, HTTP smoke + Chromium acceptance, lineage deploy gate (image revision must equal tested checkout), then docker save | ssh into the restricted Contabo command, which loads the image; deploy-to-vps.sh is the VPS-side script that starts it (docker compose up -d --no-build --wait).

    containers.ymllineage.deployment_gate()Contabo
  9. 9

    Operator observes the truth

    The UI keeps polling runs. View stages reads actual job conclusions; View lineage unzips the artifacts in memory and shows bindings, exit codes and admission decisions. Missing or expired evidence is shown as such — never as approval.

    control.py › jobs() / lineage()factory.js
Heads-up: two deploy triggersMerging to main also fires containers.yml on push, in addition to the in-run deploy job. Both share the contabo-deployment concurrency group, so they serialise rather than race.

4Pipeline jobs, one at a time

Click a job to see its inputs, the code it invokes, the evidence it emits and when it hard-fails.

① implement

calls OpenRouterread-only token
  • System prompt forbids claiming tests ran and says repo text is data, not instructions.
  • Tools: list_files (tracked files), read_file (≤100 kB), replace_text (old text must occur exactly once), write_file (≤100 kB).
  • On HTTP 402 the output budget is halved and retried (floor 256 tokens).
  • git add -N + git diff --binary produces the patch; empty or >500 kB patches fail.
Invokes
agent.main → implement → completion → tool → safe_path, lineage.binding
Emits
factory-patch (factory.patch) · factory-implementation (implementation.json with provider receipts)
Fails when
No OPENROUTER_API_KEY · provider error · 24-turn limit · no changes · models share a provider family

② test

no network · no secrets
  • validate-patch then git apply, then build .github/ci.Dockerfile.
  • Container flags: --network none --read-only --cap-drop ALL --security-opt no-new-privileges, source bind-mounted read-only, 512 MB tmpfs.
  • The parent execute() captures stdout+stderr, hashes it, records exit_code and timing. Generated code never writes its own receipt.
  • Artifact upload uses if: always() so failures are inspectable.
Invokes
lineage validate-patch, lineage execute --name tests, Docker
Emits
factory-tests → tests.json (exit_code, output_digest, binding)
Fails when
Unsafe patch shape · protected lineage path touched · any non-zero pytest exit

③ review

calls OpenRouterdifferent provider family
  • Reviewer sees {"task","patch"} as JSON data and must answer only {"approved":bool,"reason":str}.
  • Judges task fulfilment, security, regressions and test integrity; told tests already ran in isolation.
  • Result is stamped with the patch/base/task/policy/run-attempt binding and provider receipts.
Invokes
agent.main review → review → completion, lineage.binding
Emits
factory-review → review.json
Fails when
Not approved · malformed JSON · patch >500 kB · missing key

④ publish

only job with write token
  • Generated code is never executed here; only blessed bytes are uploaded.
  • publication_gate() → upstream_jobs({implement,test,review}) demands exactly one successful job each in this run attempt, and reads the live main SHA.
  • Each GitHub blob SHA is compared with a local git hash-object before the tree is built.
  • Commit parent is the admitted base SHA; branch is factory/run-<run_id>; PR body embeds the reviewer's reason.
  • If auto_merge: merge() re-gates and merges with the exact head SHA.
Invokes
publication_gate → admit, publish.main, publish.merge
Emits
factory-lineage → lineage.json (graph, evidence, decision, approval, receipt) — also on failure
Fails when
Any evidence stale/mismatched · base moved · deleted or non-regular files · blob mismatch · PR head differs

⑤ deploy

runs only if auto_merge
  • Re-runs the full test suite on main (not the patch) under the same isolation.
  • Image build args: FACTORY_VERSION=git describe …, FACTORY_REVISION=git rev-parse HEAD; label must equal HEAD.
  • Stages on 127.0.0.1:18888 → smoke.py (health, version, UI, legacy endpoints 404, auth) → Playwright Chromium + real artifact download.
  • lineage deploy needs tests, container, browser receipts and matching image revision.
  • Ephemeral SSH key is written, used, and erased in an if: always() step.
Invokes
containers.yml, lineage execute ×4, deployment_gate
Emits
deployment-tests · browser-acceptance · deployment-lineage
Fails when
Any receipt missing/failed · revision mismatch · SSH secrets absent

5Inside the lineage gate

admit(action, context, records, current_base, resource) is the single choke point for publish, merge and deploy. It is fail-closed: any exception means the action does not happen.

What gets built on every call

Model calls from OpenRouter are added as agent nodes that produced the implementation and review observations.

Checks, in order

1
Evidence presentEmpty record set → Mandatory evidence is absent.
2
check_record() per recordSchema/kind correct · binding equals current context (patch, base, task, policy, run, attempt) · age < 24 h · kind-specific success (patch_produced + receipts, approved:true, exit_code==0).
3
Base driftIf live main ≠ base_sha, a ChangeEvent invalidates base-dependent evidence in the EvidenceStore.
4
Approval brokerApprovalBroker.issue() (5-min TTL, scoped to the action) then admit() against a PolicySnapshot that allows only this action on this resource.
5
DecisionNot allowed → RuntimeError('Lineage gate blocked action: …'); the failure is still written into lineage.json.
What this does and doesn't proveRelative to a complete declared dependency model, trusted evidence producers and a policy snapshot, an action cannot rely on stale or mismatched evidence. It is not a proof that generated code is semantically correct or safe.

6Reading results back

The UI never keeps run history. Each button calls through Contabo to GitHub at click time.

View stages

GET /runs/{id}/jobs → GitHub actions/runs/{id}/jobs. Shows name, conclusion, completion time per job.

View lineage

GET /runs/{id}/lineage lists allow-listed artifacts, follows the 302 to the signed blob URL (token not forwarded; host must be *.blob.core.windows.net), unzips ≤2 MB in memory and verifies each record binds the requested run & repo.

Version badge

GET /api/version returns FACTORY_VERSION + 40-hex FACTORY_REVISION baked into the image. Pre-login, refreshed every 30 s. Missing metadata is displayed as unavailable.

PausingOpening evidence sets inspecting=true, which stops refresh from overwriting the panel (including in-flight requests). Press Refresh to resume.

8How to start it

Three ways to run the application. Pick the one that matches what you want to see.

  1. Install runtime dependencies (Python 3.12+)
    PowerShell
    python -m pip install -r requirements-runtime.txt
  2. Create an operator password hash — prompts, prints pbkdf2_sha256$600000$…
    PowerShell
    python deploy/hash_password.py
  3. Set credentials — use single quotes so $ isn't expanded
    PowerShell
    $env:FACTORY_USERNAME = 'operator'
$env:FACTORY_PASSWORD_HASH = 'pbkdf2_sha256$600000$<salt>$<hash>'
  4. Run the API + UI
    PowerShell
    python -m uvicorn ui.control:app --host 127.0.0.1 --port 8000
  5. Open http://localhost:8000, log in with the username/password, and paste a GitHub token with Actions: read & write on the repository.
bash
# 1. deps
python -m pip install -r requirements-runtime.txt
# 2. hash (prompts for a password)
python deploy/hash_password.py
# 3. credentials
export FACTORY_USERNAME=operator
export FACTORY_PASSWORD_HASH='pbkdf2_sha256$600000$<salt>$<hash>'
# 4. serve
python -m uvicorn ui.control:app --host 127.0.0.1 --port 8000

Compose refuses to start without FACTORY_USERNAME and FACTORY_PASSWORD_HASH. The image is built with version metadata so the page badge works.

bash
docker build \
  --build-arg FACTORY_VERSION="$(git describe --tags --long --always --abbrev=12)" \
  --build-arg FACTORY_REVISION="$(git rev-parse HEAD)" \
  -t trustworthy-agent-factory:production .

export FACTORY_USERNAME=operator
export FACTORY_PASSWORD_HASH='pbkdf2_sha256$600000$<salt>$<hash>'
docker compose -p trustworthy-agent-factory up -d --no-build --wait

Then open http://localhost:8010. Health: curl http://localhost:8010/api/health. Without build args the badge honestly reads “Production version unavailable”.

Production is normally started by the pipeline (job ⑤ / containers.yml), not by hand. To reach the live panel, tunnel in:

bash
ssh -N -L 8010:127.0.0.1:8010 root@85.239.245.237
# then browse http://localhost:8010

Gotchas

  • github() hard-codes MrKyaw/trustworthy-agent-factory; a fork must edit ui/control.py.
  • Plain HTTP exposes Basic-auth + token: use the SSH tunnel or HTTPS.
  • Running locally still dispatches real workflows and, with a task, real paid model calls.
